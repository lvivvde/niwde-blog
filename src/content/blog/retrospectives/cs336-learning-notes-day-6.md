## 2026-10-03

### 4D 并行与专家并行

#### 今天学到的内容与我的理解

这节课主要学习了大模型训练中的多种并行方式，包括数据并行、FSDP、张量并行、流水线并行，以及 MoE 使用的专家并行。课程把多种方案组合起来讲解了所谓的 4D 并行。

我目前的初步理解是：单张 GPU 放不下模型或训练速度不够时，就需要从不同方向拆分计算和存储。有的方案拆分训练数据，有的拆分模型内部的矩阵，有的按模型层数切分，还有的把不同专家放到不同 GPU 上。

#### AI 的整理与纠偏

“几维并行”表示同时沿几个相互独立的方向切分训练任务。不同资料对 4D 的具体命名可能略有差别，因此更重要的是理解每种方案到底切分了什么。

| 并行方式 | 切分对象 | 主要通信 | 主要目的 |
| --- | --- | --- | --- |
| 数据并行（DP/DDP） | batch 中的训练样本 | 同步梯度，常用 all-reduce | 增加训练吞吐量 |
| 分片数据并行（FSDP/ZeRO） | 参数、梯度、优化器状态 | all-gather、reduce-scatter | 降低每张 GPU 的显存占用 |
| 张量并行（TP） | 一层内部的矩阵或隐藏维度 | 频繁交换激活值和部分结果 | 拆分单层计算与参数 |
| 流水线并行（PP） | 模型的不同层 | 在阶段之间传递激活值和梯度 | 拆分模型深度 |
| 序列/上下文并行（SP/CP） | token 序列长度 | 交换 Attention 所需的数据 | 支持更长上下文 |
| 专家并行（EP） | MoE 中的专家 | 根据路由结果执行 all-to-all | 分散大量专家参数与计算 |

**FSDP 通常属于数据并行体系。**普通 DDP 在每张 GPU 上保存完整模型，只拆分 batch，然后同步梯度；FSDP 或 ZeRO 进一步把参数、梯度和优化器状态也切分到不同 GPU。计算某一层时再临时收集所需参数，反向传播后重新分散梯度。因此，FSDP 更准确地说是“带模型状态分片的数据并行”，不一定算作和数据并行完全独立的一维。

**张量并行切分的是同一层。**例如一个很大的矩阵乘法可以按行或列拆到多张 GPU，每张卡计算一部分，再合并结果。它在一层之内频繁通信，因此通常需要 NVLink、NVSwitch 等高速互连。

**流水线并行切分的是模型深度。**例如前几层放在 GPU 0，后几层放在 GPU 1。数据会像流水线一样依次经过各个阶段。为了减少某张 GPU 等待其他阶段的空闲时间，通常还要把 batch 拆成多个 micro-batch，但仍可能出现 pipeline bubble。

**专家并行针对 MoE。**不同专家可以分布在不同 GPU 上，路由器先决定每个 token 应该进入哪些专家，再通过 all-to-all 把 token 的隐藏向量发送到相应设备。专家计算完成后，还要把结果送回原来的 token 位置。它节省了单卡保存全部专家参数的压力，同时带来了较高的跨卡通信成本。

**4D 并行不是一种新的独立算法，而是多种切分方式的组合。**常见组合会同时使用数据、张量、流水线和序列/上下文并行；MoE 模型还可能加入专家并行。训练系统需要根据模型结构、显存容量、GPU 数量和互连带宽，决定每个维度使用多少张 GPU。

可以先用一句话记忆这些区别：

```text
数据并行切 batch，张量并行切宽度，流水线并行切深度，
序列并行切长度，专家并行切专家，FSDP 再把数据并行中的模型状态分片。
```
