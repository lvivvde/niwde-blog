## 2026-09-28

### 模型架构：残差流与归一化

#### 今天学到的内容与我的理解

今天的课程进入 Transformer 的架构选择，讲到了残差连接、LayerNorm 和 RMSNorm。这部分有不少我还不熟悉的公式与设计经验，所以目前主要是在接收和整理，暂时还不能独立推导它们为什么有效。

我的初步印象是：为了让残差流保留一条容易传递信息和梯度的路径，可以把 LayerNorm 放到残差分支内部，而不是放在残差相加之后。课程还比较了原来的 LayerNorm 与更简化的 RMSNorm：后者的公式不再减去均值。我听到这里时，把“减少数据搬运”和“增加计算量”连在了一起，以为换成新公式会做更多计算。这一点需要纠正。

#### AI 的整理与纠偏

- **Pre-Norm 与残差流：**把一个模块简写为 `F`，Post-Norm 近似是 `Norm(x + F(x))`，Pre-Norm 近似是 `x + F(Norm(x))`。后者让残差相加后的主路径不必再经过归一化，梯度也有更直接的传递路径；归一化仍在分支里，并不是完全删掉了。这里说的“残差流干净”，可以先理解为**保留这条直接的残差路径**，而不是说数据从此不发生变化。
- **LayerNorm 与 RMSNorm：**LayerNorm 会先求均值 `μ`，用 `x − μ` 居中，再按方差缩放，通常还带缩放与偏置参数。RMSNorm 用 `x` 的均方根缩放，不做减均值的居中步骤，常见形式也不加偏置。因此，它**减少了归一化本身的运算和参数**，并不是让计算量变大很多。
- **为什么仍要关注搬运：**归一化的 FLOPs 相比大型矩阵乘法很少，但读取、写回张量也需要时间；运行耗时不能只用 FLOPs 判断。少做一些归一化步骤可能降低耗时，实际收益还取决于实现能否融合操作、是否需要多次读写以及硬件特性。这与“大矩阵乘法计算量大、却能反复复用已搬入的数据”是两种不同情况。

现阶段我先记住两条线索：**Pre-Norm 关乎残差路径和训练稳定性；RMSNorm 关乎归一化方式及其运行成本。**后续再结合代码和公式逐步消化。

相关资料：[Stanford CS336 第 3 讲讲义](https://github.com/stanford-cs336/lectures/blob/main/lecture_03.pdf)、[RMSNorm 论文](https://arxiv.org/abs/1910.07467)、[Pre-LN 梯度分析论文](https://arxiv.org/abs/2002.04745)。

### RoPE：用旋转表示位置信息

#### 我的理解

后来学到 RoPE（Rotary Position Embedding，旋转位置编码）。我把它想成二维平面中的旋转：假设序列里的两个 token 位于相邻位置，它们因位置而产生的旋转角度相差 30°；如果在前面增加若干 token，两者各自的旋转角度都会增加，但**由位置带来的相对角度差**仍是 30°。我由此理解到，模型可以关注两个 token 相隔多远，而不只看它们各自在序列中的编号。课程里也提到，许多现代大模型采用 RoPE。

#### AI 的整理与补充

- **绝对位置怎样带出相对位置：**RoPE 实际上先按各自的**绝对位置**旋转注意力中的查询向量 `Q` 和键向量 `K`；计算它们的点积时，位置部分可以化为两者的**相对位置差**。在单组二维坐标里，若位置 `i` 的旋转角为 `iθ`，位置 `j` 的角为 `jθ`，两者的角差就是 `(j − i)θ`。同时把位置都往后移 `k`，角差不变。真实模型会把向量的多个维度两两配对，并用不同的旋转频率，不是给整个 token 只转一个固定的 30°。
- **例子的边界：**“1 和 2”适合代表序列中两个 token 的**位置**，而不是说数字 1、2 本身有固定夹角。前面真插入新的 token 后，两个位置的编码关系仍可保持同样的相对差距，但上下文也可能改变 `Q`、`K` 的内容，因此最终注意力分数不保证完全一样。
- **使用情况：**RoPE 是常见的位置编码方案，课程讲义列出了 GPT-J、PaLM、LLaMA 等例子；这不意味着所有模型都采用它，也不意味着它在任何场景都优于其他方法。

一句话复盘：**RoPE 按绝对位置旋转 `Q`、`K`，让注意力点积中的位置关系体现为相对距离。**

相关资料：[Stanford CS336 第 3 讲讲义](https://github.com/stanford-cs336/lectures/blob/main/lecture_03.pdf)、[RoFormer 原论文](https://arxiv.org/abs/2104.09864)。

### KV Cache：缓存什么，以及 MHA、MQA、GQA、MLA 的区别

#### 我的疑问与类比

课程随后讲到推理阶段的 KV Cache。我一开始把它理解成共享内存或共享数据库：模型把每一步的推理结果存起来，后续计算直接读取，以减少昂贵的数据搬运。我不确定这些步骤是分别使用内存，还是共同写入同一块内存；也不确定这是否类似服务器和分布式系统中把数据放在靠近计算的位置。

课程还介绍了多头注意力、多个查询头共享一组 KV，以及分组共享 KV。后来我查到 DeepSeek 使用了“潜在”的方案，感觉一些新模型已经不只使用课程前面介绍的几种结构。

#### AI 的整理与纠偏

- **KV Cache 用于自回归推理，不是“分开训练”。**生成第 `t` 个 token 时，每一层都会算出当前 token 的 `Q_t`、`K_t`、`V_t`。未来步骤还要用历史 token 的 K、V，所以把 `K_t`、`V_t` 追加到该层的缓存；旧的 Q 通常不再需要。下一步只计算新 token 的 Q、K、V，再让新 Q 与缓存中的历史 K、V 做注意力，避免重新计算全部历史 token 的 K、V。
- **它更像一次会话的工作区，而不是所有请求共用的数据库。**从逻辑上看，每个推理请求、每一层都有自己的 KV 序列，并随着生成逐步增长。实现上可以从统一的显存池按块分配，把多个请求装进一个批次；若服务系统支持前缀缓存，相同前缀还可能共享部分块。但这属于内存管理优化，不等于所有用户把 KV 混在同一个缓存里。
- **你的系统类比抓住了“局部性”，但对象不同。**KV Cache 确实是用显存换计算：把已经算好的中间表示留在 GPU 附近，减少重复计算。不过每生成一个 token，仍要读取越来越长的历史 KV，因此长上下文和大批量推理会消耗大量显存容量与带宽。优化目标既包括少算，也包括让缓存更小、少搬数据。

三种常见注意力结构的区别，可以先记成：

| 结构 | Q 头与 KV 头的关系 | KV Cache 特点 |
| --- | --- | --- |
| MHA（多头注意力） | 每个 Q 头都有各自的 K、V 头 | 表达能力强，缓存最大 |
| MQA（多查询注意力） | 所有 Q 头共享一组 K、V | 缓存最小，但可能损失一些效果 |
| GQA（分组查询注意力） | 每组 Q 头共享一组 K、V | 在效果和缓存大小之间折中 |

这里更准确的说法是“多个 **Q 头**共享 K、V”，不是“多个 QK 共享一个 KV Cache”。K、V 头的数量越少，每个 token 需要缓存和读取的数据通常越少。

- **DeepSeek 使用的是 MLA。**MLA（Multi-head Latent Attention，多头潜在注意力）不只是减少 KV 头的数量，而是把每个 token 的 K、V 信息联合压缩成维度更小的潜在向量，推理时主要缓存这个压缩表示；为了配合 RoPE，还需缓存一小部分与位置有关的信息。它仍然使用缓存，只是改变了缓存的内容。DeepSeek-V2 论文报告其 MLA 相比 DeepSeek 67B 将 KV Cache 减少了 93.3%。
- **MLA 没有让 MQA、GQA 全部过时。**这些方案都在权衡模型效果、缓存容量、显存带宽、计算量和硬件实现。DeepSeek 系列采用 MLA 是一个重要方向，但不能由此推断新的国产或开源模型都不再使用 MQA、GQA。

一句话复盘：**KV Cache 保存每层历史 token 的 K、V，避免重复计算；MQA、GQA 通过共享 K、V 缩小缓存，MLA 则进一步把 K、V 压缩成潜在表示。**
