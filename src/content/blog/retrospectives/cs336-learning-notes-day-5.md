## 2026-10-02

### 第 6、7 讲：GPU Kernel 与多卡并行

#### 当前的学习状态与感受

今天主要看了课程的第 6、7 讲。这两讲涉及 GPU 架构、CUDA 编程、Triton、PTX，以及多张 GPU 之间的通信和并行训练。课程还提到了 JAX、XLA 一类由编译器帮助安排计算和切分的方案。

因为我之前没有做过人工智能训练，也没有写过 GPU 程序，所以这两讲看得比较模糊。课程展示了很多底层代码和硬件概念，但它们暂时无法和我已有的开发经验联系起来，我还没有建立起一套能够解释这些代码为什么这样写的心智模型。

这次学习更多是知道这些概念存在，并没有真正掌握。我目前也不确定以后是否会直接使用它们，希望自己做 Agent 应用开发和日常调试时，不需要深入到 CUDA、Triton 或分布式训练的底层实现。

#### AI 的整理与补充

第 6、7 讲可以先压缩成两条主线：

```text
第 6 讲：如何让一张 GPU 高效完成计算
第 7 讲：一张 GPU 不够时，如何让多张 GPU 协作
```

**第 6 讲主要讨论 GPU Kernel。**PyTorch 中的一次张量操作，最终需要由 GPU 上的 kernel 执行。CUDA 允许开发者细致控制每个线程做什么；Triton 提供了更高一层的编程方式，主要从线程块和数据块的角度描述计算，再编译成 GPU 能执行的 PTX。课程通过 GeLU、Softmax、行求和和矩阵乘法等例子，继续说明分块、算子融合、共享内存和减少显存读写。

可以暂时建立下面这条关系：

```text
PyTorch 张量操作
    ↓
框架内置 kernel，或者由编译器生成、自定义 Triton/CUDA kernel
    ↓
PTX 等较底层指令
    ↓
GPU 的线程、warp、SM 和内存层级执行
```

**第 7 讲主要讨论多 GPU 并行。**当模型、优化器状态、梯度和激活值无法放入一张 GPU，或者希望使用更多计算资源缩短训练时间时，就需要把数据或模型切分到多张 GPU。不同切分方法包括数据并行、张量并行、流水线并行，以及 MoE 使用的专家并行。GPU 之间通过 broadcast、all-reduce、all-gather、reduce-scatter、all-to-all 等集合通信操作交换数据。

这一讲可以先建立下面的心智模型：

```text
一张 GPU 放不下或算得太慢
    ↓
按 batch、模型宽度、模型层数或专家进行切分
    ↓
各张 GPU 完成自己的部分
    ↓
通过 NVLink、NVSwitch 或网络传输中间结果并同步
```

JAX/XLA 代表另一种使用方式：开发者描述计算和切分策略，由编译器生成并优化底层执行计划。课程使用 PyTorch 手工展示底层通信过程，是为了让这些隐藏步骤能够被看见，并不意味着应用开发者平时都要自己实现它们。

#### 这些知识与 Agent 开发的关系

如果主要开发调用现成模型 API 的 Agent，日常工作通常集中在工具调用、工作流、上下文管理、检索、记忆、评测和可靠性上，大概率不需要亲自编写 CUDA 或 Triton kernel，也不需要自己实现多 GPU 训练。

这些底层知识在以下场景中才会逐渐变得直接相关：

- 本地部署或高并发服务大模型；
- 分析推理延迟、吞吐量和显存占用；
- 对模型进行微调或大规模训练；
- 编写自定义算子或优化模型推理；
- 排查多 GPU 通信和负载不均衡问题。

因此，我目前不需要强迫自己记住所有 API 和代码细节。现阶段只要记住两个核心取舍即可：单卡优化主要在减少数据搬运，多卡优化主要在减少并隐藏设备之间的通信。以后真正遇到模型部署、性能调优或训练问题时，再回到这些章节补充细节，会更容易把知识和实际问题关联起来。
