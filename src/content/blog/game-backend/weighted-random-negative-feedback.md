我在游戏业务里遇到的随机问题包括“怎样按概率抽一次”，也包括长期分布、连续命中、长时间不命中，以及游戏过程主动改变基础概率的情况。

这份随机状态会持久化在玩家身上。玩家重登不会清空，活动切换和现实时间也不会重置。它可以看成玩家身上的一个常驻随机池。

我把问题拆成四种模型。前两种只有命中和未命中，后两种会从多个选项中选出一个；每一类再区分基础概率固定还是由业务动态传入。

文章分成两部分。第一部分只讲业务问题和处理方法。第二部分再展开公式、代码与固定种子的百万次实验。

## 第一部分：四种业务模型

| 模型 | 每次输入 | 我会采用的处理 |
|---|---|---|
| 固定二元概率 | 固定的命中率，例如 5% | 独立随机，或使用校准后的线性、倍增 PRD |
| 动态二元概率 | 业务在每次抽取前给出新的命中率 | 按本次概率累积命中与未命中的历史欠账，再做有限负反馈 |
| 固定多类别权重 | 固定的一组权重，例如 A/B/C 为 30/30/40 | 独立加权随机，或按每个选项的历史欠账调整下一次权重 |
| 动态多类别权重 | 业务在每次抽取前给出一组新权重 | 保留原欠账，按本次新权重继续记账和选择 |

### 模型一：固定二元概率

这类业务只有命中和未命中两种结果。抽卡概率固定为 5%，每次抽卡都可以直接做一次 5% 的独立随机。

独立随机的长期命中率会接近 5%，局部仍可能长时间不出。我要缩短这种等待时，会使用 PRD：前几次给较低的补偿概率，连续未命中后逐次提高，命中后重新开始。

我使用两种增长曲线。线性 PRD 每次增加固定幅度，收敛较平缓；倍增 PRD 每次翻倍，前期可以很低，后期更快到达硬保底。两种曲线的起始值都不能凭经验填写，需要按目标长期概率反算。配置写 5%，百万次运行的目标仍然是约 5 万次命中。

### 模型二：动态二元概率

这类业务仍然只有命中和未命中，基础概率会因为游戏状态而变化。比如一次攻击前是 5%，下一次变成 10%，再下一次变成 15%。这个变化来自装备、资源、角色状态等业务规则，不是 PRD 自己加出来的补偿概率。

我不会为每个新概率重置历史，也不会把“连续失败次数”硬换算到另一张 PRD 表。我给命中和未命中各记一份累计概率欠账。每次攻击前，先用业务给出的当前概率增加两边的期望份额，再根据欠账调整本次选择。

这种方法能追踪所有历史时刻的基础概率。有限负反馈仍然保留不可预测性，也能减少长时间不暴击和连续暴击。

强配额模式只适合对齐总量，不适合战斗暴击。它可能形成容易预测的节奏，还可能把命中集中在固定概率循环中的某些位置。类似蛮王这种概率随游戏状态变化的场景，我会使用有限反馈，并同时观察总误差和不同状态下的分组误差。

### 模型三：固定多类别权重

这类业务每次必须从多个选项中选出一个。比如 A、B、C 的权重是 30、30、40，三者归一化后分别占 30%、30%、40%。权重可以写成 3/3/4 或其他同比例数字，不需要预先加起来等于 1。

独立加权随机能让长期占比接近配置，不能保证百万次后严格等于 30/30/40，也不会主动限制长连出和长时间未出。

负反馈会给 A、B、C 各保存一份欠账。一个选项实际出现得比累计期望少，后续权重会提高；出现得过多，后续权重会降低。有限反馈减少极端序列，同时保留随机性。强配额模式每次选择欠账最大的选项，抽取次数落在完整配额周期时可以严格得到 30/30/40，代价是序列更规律。

### 模型四：动态多类别权重

这类业务每次仍然从多个选项中选一个，整组权重会因为业务状态变化。权重可能先是 30/30/40，后来变成 33/33/34，再变成 10/20/70。

我保留同一份 A、B、C 欠账，不在权重变化时清空。过去已经按过去的权重记账，下一次只需要按新权重增加新的期望份额。这样不需要猜测一次权重变化应该怎样折算旧状态。

有限反馈适合需要随机体验的常驻池。强配额模式适合配给、轮转等允许规律序列的场景。两者都能接受每次传入的新权重。

## 第二部分：公式、实现与实验

### 先分清基础概率和补偿概率

固定二元 PRD 同时包含两个概率：

- 基础概率是业务配置的长期目标，比如 5%；
- 补偿概率是 PRD 根据连续未命中次数算出的本次概率。

动态二元模型中的“动态基础概率”不同。它由游戏业务在每次抽取前传入，例如本次 5%、下次 10%、再下次 15%。负反馈只能以这个值为本次期望，不能把它当成 PRD 自己的递增曲线。

### 模型一：固定二元概率与 PRD 校准

设命中后重置计数。第 `n` 次尝试的补偿概率可以采用两种曲线：

```text
线性：qₙ = min(1, C × n)
倍增：qₙ = min(1, C × 2ⁿ⁻¹)
```

`C` 是需要反算的起始概率。一次周期的期望长度是每个“仍然没有命中”的概率之和，长期命中率等于期望周期长度的倒数：

```text
Pr(X ≥ n) = ∏(k=1..n-1) (1 - qₖ)
E[X]      = Σ(n≥1) Pr(X ≥ n)
长期命中率 = 1 / E[X]
```

脚本用二分法求 `C`。目标长期概率为 5% 时，线性曲线从约 0.3802% 开始，倍增曲线从约 0.0001% 开始。

| 策略 | 起始概率 | 期望命中 | 实际命中 | 最长未命中 |
|---|---:|---:|---:|---:|
| 独立随机 | 5.0000% | 50,000 | 49,747 | 210 |
| 线性递增 PRD | 0.3802% | 50,000 | 49,839 | 73 |
| 倍增递增 PRD | 0.0001% | 50,000 | 49,978 | 21 |

固定种子下，三种策略前 100 次分别命中 2、4、4 次；首次命中都在第 20 次；最长未命中分别为 44、22、21 次。完整的 0/1 原始序列保存在结果 JSON 中，不在正文铺开。

`5%` 只是本文的实验例子。实际项目可以离线生成目标概率到起始概率的查表数据，运行时不必重复求解。

[Valve 的更新说明](https://www.dota2.com/springcleaning2014/)记录了 Dota 2 使用 Pseudo Random 机制减少过分幸运或不幸运的连续触发，[脚本 API](https://developer.valvesoftware.com/wiki/Dota_2_Workshop_Tools/Scripting/API)也提供 `RollPseudoRandomPercentage`。公开资料没有给出内部公式和官方查表数据，本文的两条曲线和校准表是自己的可复现实验模型。

### 累计概率欠账

模型二、三、四共用一套记账方式。每个结果 `i` 保存一个欠账 `Dᵢ`。第 `t` 次选择前，先按本次基础概率增加期望份额：

```text
Dᵢ ← Dᵢ + pᵢ(t)
```

选择结果 `k` 后，它偿还一次实际结果：

```text
Dₖ ← Dₖ - 1
```

从零开始，任意时刻都有：

```text
实际次数 - 累计期望 = -当前欠账
```

这个等式解释了为什么动态概率不需要重置。每一次旧概率已经进入累计期望，新概率只影响本次新增的欠账。

有限负反馈用欠账调整基础概率：

```text
调整后权重 ∝ 本次基础概率 × exp(λ × 当前欠账)
```

`λ=0` 时退化为独立随机。`λ=1` 是本文使用的有限反馈示例。`λ=∞` 时不再按调整后的权重随机，而是直接选择欠账最大的可用结果。

有限反馈的百万次误差很小是这次样本的实验结果，不是“必然严格等于”的证明。强配额模式能把欠账保持在很小范围；固定权重和完整配额周期组合时，它可以得到严格计数。

### 四个公开入口

代码把四种业务输入做成四个入口。固定和动态的差异写在调用处，底层仍然可以复用 PRD 和欠账选择器。

```python
draw_static_binary(probability)
draw_dynamic_binary(current_probability)
draw_static_weighted(weights)
draw_dynamic_weighted(current_weights)
```

实际实现允许注入随机源和需要持久化的状态对象：

```python
def draw_dynamic_binary(current_probability, rng, *, selector=None):
    if selector is None:
        return rng() < current_probability

    outcome = selector.draw(
        {"hit": current_probability, "miss": 1 - current_probability},
        rng,
    )
    return outcome == "hit"


def draw_dynamic_weighted(current_weights, rng, *, selector=None):
    if selector is None:
        return weighted_choice(current_weights, rng)
    return selector.draw(current_weights, rng)
```

玩家数据只需要保存当前欠账。它不保存一百万条历史，也不根据重登、活动或时间清零。

```json
{"A": -0.2, "B": 0.6, "C": -0.4}
```

### 模型二：动态二元概率实验

实验让基础概率按 5%、10%、15% 循环。这只是为了让代码结果容易复现，不代表真实业务一定按固定周期变化。一百万次不是 3 的整数倍，所以累计期望命中数为 99,999.95。

| 策略 | 累计期望命中 | 实际命中 | 误差 | 最长连续命中 | 最长连续未命中 |
|---|---:|---:|---:|---:|---:|
| 动态独立随机 | 99,999.95 | 99,728 | -271.95 | 7 | 102 |
| 动态有限负反馈 `λ=1` | 99,999.95 | 100,001 | +1.05 | 4 | 38 |
| 动态最大欠账优先 `λ=∞` | 99,999.95 | 100,000 | +0.05 | 1 | 10 |

总量贴近期望不等于每个概率档位都贴近期望：

| 策略 | 5% 位置误差 | 10% 位置误差 | 15% 位置误差 |
|---|---:|---:|---:|
| 动态独立随机 | -192.70 | -87.30 | +8.05 |
| 动态有限负反馈 `λ=1` | -855.70 | -273.30 | +1,130.05 |
| 动态最大欠账优先 `λ=∞` | +15,154.30 | -0.30 | -15,153.95 |

强配额只追踪“命中”和“未命中”的总欠账。固定概率循环和确定性选最大欠账会互相锁定，导致命中集中在特定位置。有限反馈也会改变分组分布，只是偏移小得多。

类似蛮王的动态暴击场景不能只验总命中数。我还会按怒气、暴击率区间或战斗状态分桶检查误差。若分桶偏移不可接受，需要降低反馈强度、给选择过程加入更多随机性，或把业务状态纳入更细的校准模型。[Riot 10.23 补丁说明](https://www.leagueoflegends.com/en-au/news/game-updates/patch-10-23-notes/)可用于确认 Tryndamere 的暴击率随 Fury 改变；它没有公开 Riot 对暴击序列的内部平滑实现。

### 模型三：固定多类别权重实验

固定权重使用 A/B/C = 30/30/40。独立随机只保证统计收敛，有限反馈减少偏差和极端序列，强配额在这次一百万次实验中得到严格计数。

| 策略 | A 次数 | B 次数 | C 次数 | 最大连出 | 最大未出 |
|---|---:|---:|---:|---:|---:|
| 独立随机 | 300,089 | 299,875 | 400,036 | 17 | 37 |
| 有限负反馈 `λ=1` | 300,000 | 300,001 | 399,999 | 6 | 14 |
| 最大欠账优先 `λ=∞` | 300,000 | 300,000 | 400,000 | 2 | 4 |

### 模型四：动态多类别权重实验

一百万次抽取分为三个阶段：333,333 次 30/30/40，333,333 次 33/33/34，333,334 次 10/20/70。表中误差是每个阶段的实际次数减去该阶段累计期望。

| 策略 | 阶段权重 | A 误差 | B 误差 | C 误差 |
|---|:---:|---:|---:|---:|
| 动态独立随机 | 30/30/40 | +121.10 | -206.90 | +85.80 |
| 动态独立随机 | 33/33/34 | +122.11 | -8.89 | -113.22 |
| 动态独立随机 | 10/20/70 | -231.40 | +46.20 | +185.20 |
| 动态有限负反馈 `λ=1` | 30/30/40 | +1.10 | -0.90 | -0.20 |
| 动态有限负反馈 `λ=1` | 33/33/34 | -0.89 | +1.11 | -0.22 |
| 动态有限负反馈 `λ=1` | 10/20/70 | +0.60 | -0.80 | +0.20 |
| 动态最大欠账优先 `λ=∞` | 30/30/40 | +0.10 | +0.10 | -0.20 |
| 动态最大欠账优先 `λ=∞` | 33/33/34 | +0.11 | +0.11 | -0.22 |
| 动态最大欠账优先 `λ=∞` | 10/20/70 | -0.40 | +0.20 | +0.20 |

这里的权重按大阶段改变，欠账有足够多的抽取逐步消化，所以有限反馈和强配额都紧贴每段期望。若业务权重按固定短周期反复变化，仍要像模型二一样检查周期位置偏置。

这套记账方式与 [NGINX 平滑加权轮询源码](https://github.com/nginx/nginx/blob/master/src/http/ngx_http_upstream_round_robin.c#L623-L653)有相似结构：每轮给候选项增加当前权重，选中一项后再扣除总权重。本文额外保留了有限强度的随机选择。

### 实验口径与复现

所有策略都使用固定种子 `20260912`，分别真实运行 1,000,000 次。固定种子让结果可以逐项复现，不代表多种子下的置信区间。本文没有额外跑多种子实验。

完整代码和生成结果位于 `scripts/weighted_random/`：

```bash
npm run test:weighted-random
npm run simulate:weighted-random
```

也可以指定抽取次数与种子：

```bash
python3 scripts/weighted_random/simulate.py \
  --draws 1000000 \
  --seed 20260912
```

生成文件包括：

- `million-draws.json`：四组完整结构化数据和模型一的前 100 次原始序列；
- `million-draws.md`：期望、实际、误差与连续段的完整表格；
- `streak-extremes.svg`：固定多类别模型的最长极端序列图。

这四种模型解决的是不同的输入形态。固定二元概率可以使用经过校准的 PRD。动态二元概率要累计每次业务传入的期望，并警惕状态分组偏置。固定多类别权重可以在随机体验和严格配额之间调节。动态多类别权重沿用同一份欠账，用每次的新权重继续记账。
