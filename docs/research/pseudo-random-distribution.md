# 游戏二元伪随机分布（PRD）研究笔记

> 调研日期：2026-09-12
> 范围：二元递增概率补偿、目标长期概率到初始常数的校准、术语核对，以及基础概率动态变化时的处理。
> 证据标准：厂商官方页面、公开源码、论文或政府技术文档。数学结论在本文中直接推导。

## 结论摘要

1. `h_n = min(1, Cn)` 是一个数学上完整的“线性递增条件命中率”模型。给定目标长期命中率 `p`，`C` 不能简单取 `p/2`，而应由期望周期长度方程数值求解。
2. Valve 的一手材料证实 Dota 2 使用名为 Pseudo Random 的机制，目的包括减少过分幸运或不幸运的连续触发；公开脚本 API 也暴露了 `RollPseudoRandomPercentage`。但没有找到 Valve 公开的内部公式或官方 `C` 表。因此博客应称 `min(1, Cn)` 为“常见的 Dota 风格线性 PRD 模型”，不能声称它就是当前 Dota 2 的已公开源码实现。
3. 线性 PRD 校准的是长期平均命中率，不保证任意有限样本（包括 100 万次）恰好等于目标次数。若业务要求有限前缀误差有硬界，应改用累计欠账/比例舍入一类算法。
4. 没有查到“整备概率”是本领域术语。有官方证据的相近术语是“基础概率”和“综合概率（consolidated probability）”，但它们描述两个统计口径，不是两种快慢不同的收敛算法。
5. 线性、倍增/指数等递增曲线都可以设计，但每条曲线都必须独立校准。没有证据表明“线性 PRD 与某个固定名称的第二种 PRD”是统一行业标准。
6. 当基础概率逐次变化时，静态 `C(p)` 查表的更新与重置没有公认的、保留原保证的转换规则。若目标是追踪 `sum p_t`，累计欠账模型比强行迁移 PRD 连败计数更自然。

## 一手资料能证明什么

- Valve 的 [2014 Spring Cleaning 更新](https://www.dota2.com/springcleaning2014/)明确写到 Counter Helix 和 Moment of Courage 改用 Pseudo Random chance，并解释其效果是减少特别幸运或不幸运的连续触发。
- Valve 的 [Dota 2 6.87 更新](https://www.dota2.com/687)记录了闪避改用 Pseudo-Random Distribution。
- Valve Developer Community 的 [Dota 2 脚本 API 索引](https://developer.valvesoftware.com/wiki/Dota_2_Workshop_Tools/Scripting/API)公开了 `RollPseudoRandomPercentage(chance, randomId, unit)` 接口；Dota 2 中国官网的 [Scripting Constants](https://www.dota2.com.cn/wiki/Dota_2_Workshop_Tools/Scripting/Constants.htm)还列出了按暴击、闪避、物品等用途区分的 pseudo-random ID。
- 上述一手材料没有公开 `C` 的计算式、查表数据或状态迁移细节。网上常见表格可以用本文方程复算，但不应包装成 Valve 官方表。
- Riot 的 [10.23 官方补丁](https://www.leagueoflegends.com/en-au/news/game-updates/patch-10-23-notes/)证实 Tryndamere 的暴击率随 Fury 改变；它可以作为“动态基础概率”的业务动机，但该页面没有公开 Riot 如何平滑暴击序列。

因此，文章可以说“受游戏 PRD 思路启发”，不应说“复刻 Dota 2/英雄联盟真实算法”。

## 线性递增 PRD 的严格定义

设一次成功后计数器重置。自上次成功起，第 `n` 次尝试的条件命中率为：

```text
h_n(C) = min(1, nC),  n = 1, 2, ...
```

设随机变量 `X` 为相邻两次成功之间包含的尝试次数，`M = ceil(1/C)` 为最晚必中的尝试序号。要走到第 `n` 次，前 `n-1` 次必须全部失败，所以：

```text
Pr(X >= n) = product(k = 1..n-1, 1 - min(1, kC))
```

利用非负整数随机变量的尾和公式：

```text
E[X] = sum(n = 1..M, Pr(X >= n))
```

每个周期恰有一次成功，因此长期成功率是：

```text
P(C) = 1 / E[X]
```

要得到目标长期概率 `p`，求解：

```text
P(C) = p
```

`P(C)` 随 `C` 单调增加，可在 `(0, 1]` 上用二分法求根。运行时可以直接求解并缓存，也可以离线生成查表；若查表网格较粗，插值会引入额外误差，应在测试中重新计算表项对应的实际长期率。

### 复算表

下表由上述方程高精度二分得到，不是厂商官方数据：

| 目标长期率 `p` | 初始常数 `C` | 最晚必中的尝试 `ceil(1/C)` |
| ---: | ---: | ---: |
| 1% | 0.000156041692 | 6409 |
| 5% | 0.003801658304 | 264 |
| 10% | 0.014745844781 | 68 |
| 15% | 0.032220914373 | 32 |
| 20% | 0.055704042950 | 18 |
| 25% | 0.084744091852 | 12 |
| 30% | 0.118949192725 | 9 |
| 40% | 0.201547413608 | 5 |
| 50% | 0.302103025349 | 4 |
| 75% | 0.666666666667 | 2 |

例如目标长期率为 50% 时，线性 PRD 的条件概率约为 `30.21% → 60.42% → 90.63% → 100%`，而不是 `25% → 50% → 100%`。后一序列的期望周期长度为：

```text
1 + 0.75 + 0.75 * 0.5 = 2.125
```

所以其长期命中率为 `1 / 2.125 ≈ 47.06%`。

## “收敛快慢”必须先定义指标

独立 Bernoulli 抽样每次条件概率恒为 `p`，等待次数服从几何分布，尾部没有硬上限。NIST 的[指数分布说明](https://www.itl.nist.gov/div898/handbook/apr/section1/apr161.htm)给出了连续时间中“恒定 hazard”的对应性质。

线性 PRD 使用随连败次数线性上升的 hazard，并在 `ceil(1/C)` 次硬保底。其他可选曲线包括：

```text
线性：       h_n = min(1, Cn)
倍增/几何：  h_n = min(1, C * r^(n-1)), r > 1
渐近指数：   h_n = 1 - (1-C)^n
幂次：       h_n = min(1, C * n^gamma)
```

可靠性工程中的 Weibull 族正式展示了 shape 参数如何产生恒定、递增或递减 hazard，见 NIST 的 [Weibull 模型](https://www.itl.nist.gov/div898/handbook/apr/section1/apr162.htm)及[离散 Weibull hazard](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/diwhaz.htm)。这能作为设计曲线族的数学参照，但不是游戏行业对某个具体 PRD 变体的命名标准。

比较“更快/更慢”时至少应明确是在比较：达到 100% 的尝试数、等待时间方差、长尾概率，还是蒙特卡洛累计比例接近目标的速度。不同曲线必须先各自校准到相同长期率，再比较这些指标；直接使用相同 `C` 比较没有意义。

## “整备概率”的术语核对

本次检索没有找到“整备概率”作为游戏概率或统计学标准术语的可靠来源，不能擅自纠正。可能需要作者回忆原文、课程或英文拼写。

一个确有一手资料的相近概念是“基础概率”与“综合概率”：HoYoverse 在[「捕获明光」官方说明](https://www.hoyolab.com/article_pre/18014398241030396)中同时公布 base probability 与 consolidated probability，后者计入保障机制后的总体口径。它们不是两种递增曲线，也不表示一个收敛快、一个收敛慢。

另一个可能被口述混淆的概念是“线性递增”和“倍增/指数递增”，但没有用户原始出处时只能列为待确认，不能认定“整备”就是其中任何一个。

## 基础概率动态变化时

静态 PRD 的校准利用了“每个成功周期采用同一条 hazard 曲线”这一前提。若第 `t` 次业务给出的目标概率为 `p_t`，以下常见做法都不自动继承静态保证：

- 每次变化就重置失败次数：频繁变化会反复回到较低初始概率，可能产生系统性偏差。
- 保留失败次数、把 `C` 换成 `C(p_t)`：本次条件概率可计算，但 `P(C)=p` 的静态周期证明已经不适用。
- 把旧曲线的累计失败分位映射到新曲线：这是可定义的产品策略，但离散状态需要取整，且“保留次数、保留累计 hazard、保留分位”是不同公平语义，没有唯一标准答案。

没有找到游戏厂商或标准公开一种“动态 `p_t` 下的 PRD 状态换算公式”。因此不建议博客声称存在行业公认转换办法。

若真正的要求是：实际成功次数追踪每次当时概率的累计期望，可以维护欠账：

```text
D(t+1) = D(t) + p_t - y_t
```

其中 `y_t` 为本次是否成功（0 或 1）。于是恒有：

```text
sum(t=1..T, y_t) - sum(t=1..T, p_t) = D(1) - D(T)
```

只要算法能令 `D(T)` 有界或为 `o(T)`，长期实际率就会追踪动态累计目标，不需要回算过去概率。这个恒等式本身不保证某个有限强度的随机反馈一定有界；该保证需要另行证明或通过实验界定。

“最大欠账优先”的确定性极限有成熟工程类比：NGINX 官方[平滑加权轮询源码](https://github.com/nginx/nginx/blob/master/src/http/ngx_http_upstream_round_robin.c#L623-L653)每轮给候选项累加有效权重，选择当前权重最大项，再从选中项减去总权重。它与累计份额调度同构，但不是随机抽样。

学术上，Knuth 的 [Two-way rounding](https://arxiv.org/abs/math/9504228)证明了对实数序列进行 0/1 舍入并控制前缀误差的可行性；[Online Proportional Apportionment](https://arxiv.org/abs/2510.14752)则研究了逐时到达份额、不可撤销分配和累计份额误差，也指出多类别全局 quota 存在一般性限制。这些工作支持“动态权重应按每次当时的份额累计”，但不能直接当作任意指数反馈公式的证明。

## 对博客实现与实验的建议

- 将二元章节命名为“校准后的线性递增 PRD”，将 `C` 求解器作为可复现脚本的一部分。
- 同时输出理论长期率与蒙特卡洛观测率；不要把观测计数恰等于目标当作 PRD 正确性的必要条件。
- 对线性、倍增/指数曲线分别求解参数，再比较平均等待、标准差、P95/P99 等待次数、连续成功率和硬保底位置。
- 动态 `p_t` 单独作为实验，不复用静态结论。至少比较“变化时重置”“保留次数换表”“累计欠账反馈”三种策略。
- 对动态模型报告 `actual(T) - sum(p_t)` 的前缀最大绝对误差；这是比只看最终比例更直接的公平性指标。
- 所有持久化状态应按玩家与事件池/概率机制版本隔离。概率为零时禁止命中；事件语义改变时通过版本迁移或重置，不能只改权重表。

## 写作时应保留的证据边界

- 可以写：Valve 官方说明 PRD 用于压低极端幸运/不幸运连串。
- 可以写：`min(1, Cn)` 经过本文方程校准后，长期率严格等于目标值（在精确数学模型下）。
- 不应写：Valve 或 Riot 已公开并采用本文的具体公式、C 表或动态状态迁移规则。
- 不应写：100 万次模拟必然恰好命中目标次数；蒙特卡洛是验证统计行为，不是制造数学等式。
- 暂不写：“线性概率”和“整备概率”是两个正式算法名。应先确认原始出处，再决定是“基础/综合概率”还是“线性/倍增曲线”。

后续设计确认选择在线性递增之外增加“倍增递增”作为本文自行定义并校准的对照曲线；这项编辑选择不代表已经确认口述中的“整备概率”就是“倍增概率”。
